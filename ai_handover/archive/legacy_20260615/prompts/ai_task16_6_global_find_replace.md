너는 이 저장소(`product_test_tracing_system`, FastAPI+SQLite, Windows)의 admin 화면에 **전역 찾아 바꾸기(Ctrl+H)** 를 구현한다. Ctrl+H로 모달을 열고 [찾을 텍스트]/[바꿀 텍스트]를 입력하면 **모든 표의 셀 텍스트**를 일괄 치환·저장한다. **코드만(JS/템플릿/CSS, 필요시 라우트). DB 스키마 변경 없음.**

## 기존 인프라 (재사용)
- 셀 저장 = `POST /admin/api/product-test/fields/bulk-update`, 요청은 `updates: [{entity_type, entity_id, field_name, value}, ...]` **리스트**(한 번에 다건 가능).
- `app/static/js/admin-incell-edit.js` — 셀이 `entity_type/entity_id/field_name` 매핑을 들고 있음. 치환 저장도 이 매핑을 그대로 사용.
- 자유 편집 정책(16-5): 실제 컬럼 셀은 PK/FK 포함 편집 허용. 파생/계산 셀(대응 컬럼 없음)은 저장 대상 아님.

## 동작 사양
1. **Ctrl+H** 전역 keydown 핸들러 → 브라우저 기본동작(방문기록) `preventDefault` 후 **인페이지 모달** 오픈. (모달은 현재 페이지 내. Trace 규칙처럼 새 창/새 페이지 금지.)
2. 모달 입력: **찾을 텍스트**, **바꿀 텍스트**, 옵션 — ① 범위(현재 탭의 표 / **모든 탭의 모든 표**, 기본=모든 표) ② 부분일치(substring) vs 셀 전체일치 ③ 대소문자 구분.
3. **미리보기/확인**: 적용 전 "변경될 셀 N개"를 집계해 보여주고 확인받는다(대량 변경이라 필수). 저장 대상 불가 셀(파생/매핑없음)은 집계에서 제외하고 그 수도 표시.
4. **적용**: 매칭된 **실제 컬럼 셀**의 텍스트에서 old→new 치환한 값으로 `updates` 배열을 만들어 `bulk-update`에 보낸다(건수 많으면 청크 분할). 성공 시 화면 셀도 갱신.
5. 탭이 지연 렌더(미활성 탭 미로딩)면, "모든 표" 범위에서 누락되지 않도록 처리(필요한 표를 로드 후 스캔하거나, 미로딩 탭은 명확히 알림). 애매하면 멈추고 질문.

## ⚠️ 규칙
- **NULL 바이트 고질병**: 편집 직후 `python -c "p=r'<file>';open(p,'wb').write(open(p,'rb').read().rstrip(b'\x00'))"` → `node --check`/py_compile → `tail` 확인.
- DB 스키마 변경 금지. 저장은 기존 bulk-update 재사용(서버에 신규 일괄 엔드포인트가 더 깔끔하면 추가 가능하나, 기존 계약 깨지 말 것).
- 대량 mutation이므로 **확인 단계 필수**. 실수 방지를 위해 "변경 건수 + 표/필드별 요약"을 확인창에 노출.
- PK/FK도 치환 대상이 될 수 있음(자유편집 정책) — 위험은 사용자 감수지만, 확인창에 "PK/FK 포함 N건" 같이 구분 표기.
- Trace·모달 등 모든 UI는 현재 페이지 내에서. 모호하면 멈추고 질문.

## 검증
- 아무 표에서 Ctrl+H → 모달 오픈(브라우저 기록창 안 뜸).
- old 입력 → 매칭 셀 수 미리보기 정확 → 적용 시 모든 표의 해당 셀 치환·DB 반영, 새로고침 후 유지.
- 부분/전체일치·대소문자·범위 옵션 각각 동작.
- 파생/매핑없음 셀은 변경 안 됨(집계 제외).
- `uv run pytest tests/ -q` 전체 green, 편집 파일 NULL 0 + node --check/py_compile.

## 시작
Ctrl+H 모달 + 스캔/미리보기/확인/일괄저장 순. 미활성 탭 스캔 방식이 애매하면 멈추고 질문. 모든 UI 인페이지.
